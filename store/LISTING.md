**Description**
```
Browser automation for Claude Code through a local MCP server.

This extension connects Chrome to a small bridge process running on your own
computer (127.0.0.1). When you ask Claude Code to do something in the browser,
it can:

• List, open, close and navigate tabs
• Read page text and an accessibility tree of interactive elements
• Click, type, scroll, drag and press keys, shown by an animated on-page cursor

• Fill forms and upload local files of any size (multi-GB videos included)
• Take screenshots and read console and network logs for debugging

Requirements: the companion bridge/MCP server (Node.js) must be installed and
registered with Claude Code. Without it the extension stays idle. Setup:
<link to your README or repository>

Privacy: the extension talks only to the bridge on 127.0.0.1. It has no
analytics and sends nothing to any server of its own. See the privacy policy.

Not affiliated with or endorsed by Anthropic.
```

## Privacy practices tab

**Single purpose**
> Let the user's local Claude Code session automate and inspect the user's own Chrome tabs on request.

**Permission justifications**

| Permission | Justification |
| --- | --- |
| `debugger` | Sends trusted mouse and keyboard input, captures screenshots, evaluates diagnostics and reads console and network logs in the tab the user asked to automate (Chrome DevTools Protocol). |
| `tabs` | Lists, opens, activates, navigates and closes tabs on request, and reports tab titles and URLs to the local automation client. |
| `scripting` | Injects the page-reading and input content script into tabs that were open before installation, and runs user-requested diagnostic snippets in the page. |
| `activeTab` | Captures the visible tab for screenshots when the debugger cannot attach to the page. |
| `alarms` | Keeps the connection to the local bridge alive by reconnecting periodically, because MV3 service workers are suspended when idle. |
| `storage` | Saves the user's chosen local bridge port. |
| `userScripts` | Runs user-requested JavaScript on pages whose Content Security Policy blocks eval, only when the user has turned on "Allow User Scripts". |
| Host permission `<all_urls>` | The user can point the automation at any site they use; the content script must read and interact with that page, and uploads stream from the local bridge at 127.0.0.1. |

**Remote code:** Select **No, I am not using remote code**. All extension logic ships in the
package. JavaScript snippets the user asks for run in the *page* (like DevTools), not in the
extension's own context. If review objects, see "Review risks" below.

**Data usage**: tick **Website content** and **Web history** (page text, URLs and titles are
read when the user asks). Then certify all three:
- Not sold to third parties
- Not used or transferred for purposes unrelated to the single purpose
- Not used to determine creditworthiness or for lending

**Privacy policy URL:** host `store/PRIVACY.md` publicly (GitHub Pages, a public GitHub
repo file, Google Sites, or similar) and paste the URL.

## Distribution tab

- **Visibility:** start with **Unlisted** (only people with the link can install), or
  **Private** with named testers.
- **Regions:** all regions.

## Naming

The name describes compatibility ("for Claude Code") rather than leading with the brand,
which Web Store policy against implied affiliation requires. Keep the "Not affiliated with
or endorsed by Anthropic" line in the description.

## Review risks

- **Broad permissions** (`debugger` + `<all_urls>` + `userScripts`) mean manual review,
  typically several days to a few weeks. Clear justifications (above) help most.
- **`javascript_tool`** executes code strings supplied at run time. If a reviewer treats this
  as remote code, the fallback is a store build without `javascript_tool` and `userScripts`.
- **Companion app:** reviewers can't exercise the extension without the bridge. Put setup
  steps in the description and, if asked, in the "Test instructions" field.
